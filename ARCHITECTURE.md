# Архитектура

Документ описывает, как устроено приложение, из чего оно состоит и почему выбраны
именно такие решения. Написан так, чтобы был понятен человеку без опыта в разработке,
но при этом годился как техническое описание.

---

## 1. Общая картина

```
┌──────────────────────────────────────────────────┐
│                   Telegram                       │
│                                                  │
│   Пользователь открывает бота @schet_i_poryadok  │
│   и нажимает кнопку «Открыть»                    │
│                     │                            │
│                     ▼                            │
│   ┌────────────────────────────────────────┐     │
│   │   Окно мини-приложения                 │     │
│   │   (браузер внутри Telegram)            │     │
│   │                                        │     │
│   │   загружает страницу по адресу ────────┼─────┼──▶ GitHub Pages
│   │                                        │     │     (index.html,
│   │   Курсы · Расписание · Цены · Контакты │     │      styles.css,
│   └────────────────────────────────────────┘     │      data.js,
│                                                  │      app.js)
└──────────────────────────────────────────────────┘
```

Ключевая мысль: **приложение — это обычная веб-страница.** Telegram лишь показывает её
в своём окне. Никакой отдельной «мобильной разработки» здесь нет.

---

## 2. Из каких файлов состоит

После второго этапа проект будет выглядеть так:

```
docs/                   ← сайт лежит здесь: так его умеет публиковать GitHub Pages
├── index.html      ← каркас: какие блоки есть на странице и в каком порядке
├── styles.css      ← оформление: цвета, шрифты, отступы, размеры
├── data.js         ← содержимое: курсы, расписание, цены, телефоны
└── app.js          ← поведение: раскрытие курсов, сборка страницы из data.js
```

Разделение не случайное. У каждого файла ровно одна работа:

**`data.js` — единственный файл, который вы будете открывать регулярно.**
Здесь лежат все тексты, цены и телефоны в виде простого списка. Поменять цену
со 100 000 на 120 000 — это правка одной цифры, без риска что-либо сломать.
Ни цветов, ни разметки здесь нет.

**`index.html`** описывает скелет страницы: приветствие, курсы, расписание, цены, контакты,
кнопка внизу. Сами тексты сюда не пишутся — они подставляются из `data.js`.

**`styles.css`** отвечает за внешний вид. Все цвета собраны наверху файла в одном месте
(так называемые переменные), поэтому сменить оттенок зелёного по всему приложению —
это правка одной строки, а не поиск цвета по всему файлу.

**`app.js`** — небольшой скрипт. Он берёт данные из `data.js`, вставляет их в страницу
и обрабатывает нажатия: раскрыть курс, позвонить, свернуть обратно.

## 3. Как данные попадают на экран

```
data.js                app.js                  index.html
────────               ──────                  ──────────
courses: [       ──▶   пробегает по списку ──▶  <div class="sheet">
  {                    и для каждого курса         <button class="row">
    title: "…",        создаёт строку в              Бухгалтер с нуля
    subtitle: "…",     таблице                    </button>
    lessons: 36,                                   <div class="body">…</div>
    program: […]                                 </div>
  }, …
]
```

Тот же принцип для расписания, цен и контактов. Добавили курс в `data.js` —
на странице появилась новая строка. Ничего больше трогать не нужно.

## 4. Принятые решения и почему

### Никакой базы данных и сервера

Приложение только показывает информацию — оно ничего не запоминает и ни у кого ничего
не спрашивает. Записываются по телефону. В такой ситуации сервер был бы лишним:
его нужно оплачивать, обновлять и чинить, а пользы он бы не приносил.

Обратная сторона: чтобы поменять расписание или количество мест, нужно отредактировать
`data.js` и загрузить изменения. Это минута работы, но её нужно делать самому,
а не через удобную админку. Для двух курсов и одного расписания это честный размен.

### Хостинг на GitHub Pages

Бесплатно, без рекламы, с автоматическим защищённым соединением (`https://`),
которого Telegram требует обязательно. Каждое изменение сохраняется в истории,
поэтому всегда можно откатиться к рабочей версии.

Альтернативы — Netlify, Vercel, Cloudflare Pages — работают не хуже. Выбран GitHub Pages
как самый распространённый: если что-то не получится, инструкций в интернете больше всего.

### Никаких фреймворков

Проект написан на чистых HTML, CSS и JavaScript. Ни React, ни Vue, ни сборщиков.

Для страницы такого размера фреймворк добавил бы десятки мегабайт зависимостей,
шаг сборки и целый слой понятий, которые нужно изучить, — ради нулевой выгоды.
Здесь же любой файл можно открыть в блокноте и прочитать. Страница весит меньше
100 килобайт и открывается мгновенно даже на слабом интернете.

### Одна страница вместо разделов

Мы обсудили, что посетитель чаще всего заходит один раз: читает и записывается.
Такому человеку не нужны вкладки и навигация — он просто листает сверху вниз.
Нижние вкладки хороши для приложений, куда возвращаются регулярно; здесь они
добавили бы лишний шаг между интересом и звонком.

### Кнопка внизу всегда на виду

Кнопка «Позвонить и записаться» прилипает к нижнему краю экрана и не уезжает при
прокрутке. Что бы человек ни читал в этот момент, действие всегда под большим пальцем.
Это единственное действие в приложении, и оно намеренно одно.

## 5. Связь с Telegram

Telegram даёт странице небольшую библиотеку `telegram-web-app.js`. Она подключается
одной строкой и даёт несколько полезных вещей:

- **Тема оформления.** Telegram сообщает странице, светлая у пользователя тема или тёмная.
- **Разворот на весь экран.** По умолчанию окно открывается наполовину; одна команда
  разворачивает его полностью.
- **Кнопка внизу самого Telegram.** Мессенджер умеет показывать собственную кнопку
  под окном приложения — она выглядит роднее, чем наша.
- **Отклик при нажатии.** Лёгкая вибрация, как в обычных приложениях.
- **Данные о пользователе.** Имя и язык — можно поздороваться по имени.

Всё это необязательно, страница работает и без этого. Но именно эти мелочи отличают
«сайт в окне» от «приложения». Подключаем на третьем этапе.

## 6. Что будет, если проект вырастет

Если однажды понадобится, чтобы расписание менялось без правки файлов, а заявки
хранились и считались, — архитектура меняется так:

```
Сейчас:      Telegram → страница (тексты внутри файла data.js)

Потом:       Telegram → страница → сервер → база данных
                                      ↑
                              админка для владельца
```

Появляется сервер (например, на Python), база данных и защищённая паролем страница
для управления. Внешний вид и вёрстка при этом сохраняются полностью — меняется только
то, откуда страница берёт данные: не из `data.js`, а с сервера.

Это важное свойство выбранной структуры: переход не потребует переписывать проект заново.
Поэтому и стоит начинать с простого варианта.

---

## 7. Ограничения, о которых стоит знать заранее

Приложение открывается только внутри Telegram или по прямой ссылке в браузере —
в поиске Google его не найдут. Для ознакомительного приложения при боте это нормально,
но если понадобится приток людей из поиска, нужен обычный сайт на своём домене.

Количество свободных мест в расписании обновляется вручную. Если этого не делать,
цифры начнут врать, а это хуже, чем их отсутствие. Если поддерживать не получается —
уберите их, это одна правка в `data.js`.

Телефонные номера видны всем, кто откроет приложение. Это осознанно: они и нужны,
чтобы по ним звонили.
